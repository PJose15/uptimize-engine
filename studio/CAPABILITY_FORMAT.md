# Capability contract

Start with one useful task. Record purpose, trigger, required inputs, output artifact, procedure, permitted tools, quality checks, examples, source provenance and known limits. Mark maturity explicitly: proposed, drafted, exercised, evaluated or operational.

Evaluate a capability on a representative task before promoting it. Preserve input, output, review findings and observed cost/time where available. A capability may remain a procedure, become a deterministic script, or become a provider-native skill. Create a separate agent only when its responsibility and control of tools justify that boundary.

Provider-discovered skills can share standard SKILL.md content while keeping provider-specific metadata separate. Inspect the current official discovery paths before installing. This change supplies ordinary draft procedure documents, not installed or autonomously running agents.

Acceptance asks whether the capability produces a useful result reliably within its scope. Counts of files, specialties or agents are not a measure of operational readiness.
